1. 准备 GitHub 仓库

  • 仓库 A (网页库)：名称必须为 你的用户名.github.io。设为 Public。

  • Node.js: 运行环境。
  • Git: 版本控制与发布工具。

第五阶段：补充建议（进阶方案）

1. 自动生成 YAML 头部 (VS Code 用户必备)

为了避免每次手动写 Front Matter 报错，建议在 VS Code 中配置 User Snippets (用户代码片段)。

将你提供的 JSON 模板加入 markdown.json 中，以后只需输入 blog 即可一键生成标准头部。

2. 资源路径处理

对于嵌入式开发者，文章中经常包含实验截图。

  • 建议方案：修改 _config.yml 中的 post_asset_folder: true。
  • 效果：每次新建文章会同步生成一个同名文件夹，你直接把图片放进去，用 ![描述](图片名.png) 即可引用，方便管理。

3. 轻量化尝试：Hugo

如果你觉得 Hexo (Node.js) 在全志开发板上运行太重、生成速度慢，可以尝试 Hugo（Go 语言编写）。

  • 优势：单个二进制文件，无需安装成百上千的 npm 包，极其适合资源受限的嵌入式系统。

Linux|RTOS区别及权限

1. Linux和RTOS的区别？

通俗些讲，如果你的产品，在资源受限的芯片上运行，实时性要求高，那就使用RTOS。

如果产品功能多（网络、安全、显示、数据库等等），芯片资源丰富，那可以直接上Linux，这样开发效率更高。

2.常见Linux命令

ls（英文全拼：list files）: 列出目录及文件名

用户类型 说明
u(user) 文件所有者
g(group) 所属用户组
o(other) 其他用户

chmod （Change Mode）用于修改文件或目录的权限

测试脚本，创建test.sh，仅用于打印日志，验证权限问题，无其它功能

指令格式

3 种权限

权限 符号 数字 说明
读(Read) r 4 允许读取文件内容
写(Write) w 2 允许修改文件/在目录种创建/删除文件
执行(Execute) x 1 允许执行文件/进入目录

学习方法及路线

嵌入式学习路线

1. 嵌入式学习的三个阶段

第一阶段：裸机开发 (Bare Metal)

这是直接在芯片上“裸奔”写程序。你不需要操作系统，直接操控寄存器。

  • 重点： C语言（指针、位运算）、单片机架构（如 STM32/ARM Cortex-M）、GPIO、中断、UART、I2C、SPI。
  • 目标： 理解底层硬件是如何工作的。当你点亮第一个 LED 灯时，你就完成了硬件控制的第一步。

第二阶段：嵌入式 Linux 系统 (Embedded Linux)

当任务变得复杂（需要网络协议栈、文件系统、图形界面）时，我们就需要 Linux。

  • 重点： Linux 常用命令、Shell 脚本、交叉编译 (Cross-Compilation)、Bootloader (U-Boot)、内核移植、根文件系统构建。
  • 目标： 让 Linux 在你的开发板（如树莓派、飞凌、正点原子等）上跑起来。

第三阶段：驱动开发与应用开发

这是目前行业内需求最大的部分。

  • 应用层： 使用 C/C++、Python 或 Qt 开发运行在 Linux 上的应用程序。
  • 驱动层： 编写连接硬件与 Linux 内核的桥梁（如字符设备驱动）。

2. 快速上手的“黄金建议”

建议你不要只看书，要**“以项目驱动学习”**：

  1. 准备一块开发板： 如果你是完全的新手，STM32 是学习裸机的首选；如果你想直接攻克 Linux，树莓派 (Raspberry Pi) 或 基于 IMX6ULL 的开发板非常适合。
  2. 不要纠结于背后的深层原理： 先通过“抄”代码让程序跑通，看到现象后再去深挖底层的寄存器配置或内核源码。
  3. 拥抱 Linux 环境： 尽早抛弃 Windows 下的各种 IDE，学会使用 Ubuntu 系统，尝试在终端里用 gcc 编译你的第一个 “Hello World”。

3.学习的过程中要有所总结和记录

  1. 总结是为了整理自己学到的东西，在整理的过程中发现自己对所学的知识的掌握
  2. 记录主要有两个目的：1.自己遗忘时可随时打开回顾；2.为自己工作/升学面试所使用的简历添加内容（当然作为学生竞赛获奖也能证明自己的实力）
