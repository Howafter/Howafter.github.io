物联网常见协议简介

网络协议全面介绍

TCP (传输控制协议)

  • 层级：传输层
  • 特点：面向连接的协议，通过”三次握手”建立连接，提供确认机制、重传控制、流量控制和拥塞控制
  • 核心优势：确保数据的完整性、顺序性和可靠性
  • 应用场景：Web浏览(HTTPS)、文件传输(FTP/SFTP)、电子邮件(SMTP/IMAP)、数据库操作等
  • 与UDP对比：TCP可靠但有延迟，UDP无连接但高效

UDP (用户数据报协议)

  • 层级：传输层
  • 特点：无连接协议，无需建立连接即可发送数据，头部开销小(仅8字节)
  • 核心优势：传输效率高，延迟小
  • 应用场景：DNS、TFTP、SNMP、网络视频会议等对可靠性要求不高的应用
  • 与TCP对比：UDP不可靠但速度快，适合实时应用

HTTP (超文本传输协议)

  • 层级：应用层
  • 特点：基于TCP的协议，用于Web浏览
  • 工作原理：客户端-服务器模型，通过请求-响应机制传输数据
  • 应用场景：网页浏览、API调用等

HTTPS (安全超文本传输协议)

  • 层级：应用层
  • 特点：HTTP的安全版本，通过SSL/TLS加密
  • 工作原理：使用SSL/TLS协议创建加密链接，URL显示HTTPS和挂锁图标
  • 重要性：保护用户数据安全，防止黑客读取敏感信息
  • 应用场景：在线支付、登录认证、隐私信息传输等

SSL/TLS (安全套接字层/传输层安全性)

  • 层级：传输层安全协议
  • 特点：SSL是早期协议，现已被TLS取代，但”SSL”仍被广泛使用
  • 工作原理：通过”SSL握手”过程建立加密会话，加密传输中的数据
  • 应用场景：保护网站通信安全，确保数据传输私密性

MQTT (消息队列遥测传输协议)

  • 层级：应用层
  • 特点：基于发布/订阅模式的轻量级协议，专为物联网设计
  • 核心优势：协议头极小(固定头部仅2字节)，适合低带宽、高延迟环境
  • 服务质量(QoS)：0(最多一次)、1(至少一次)、2(恰好一次)
  • 应用场景：智能家居、工业物联网、车联网、智慧城市、医疗健康等

FTP (文件传输协议)

  • 层级：应用层
  • 特点：客户端-服务器模型，使用两个TCP连接(控制连接和数据连接)
  • 工作模式：主动模式(服务器主动发起数据连接)和被动模式(客户端主动发起数据连接)
  • 应用场景：文件上传、下载、删除等操作
  • 安全替代：FTPS(FTP over SSL/TLS)和SFTP(SSH File Transfer Protocol)

RNDIS (远程网络驱动接口规范)

  • 层级：网络层
  • 特点：基于USB的通信协议，用于在USB设备上实现TCP/IP数据传输
  • 核心机制：将网络数据包封装在USB传输中，实现”TCP/IP over USB”
  • 应用场景：嵌入式设备、移动终端与计算机之间的联网功能
  • 支持系统：微软Windows系统为主，部分Linux和Android系统通过驱动支持

ECM (企业内容管理)

  • 层级：应用层
  • 特点：用于管理非结构化数据的系统，如文档、图像等
  • 标准：CMIS(内容管理互操作性服务标准)是ECM存储库上的SQL标准
  • 应用场景：企业文档管理、内容协作、知识管理等

PPP (点对点协议)

  • 层级：链路层
  • 特点：点到点链路层协议，用于在全双工的同异步链路上进行点到点的数据传输
  • 主要组件：
    • LCP(链路控制协议)：用于各种链路层参数的协商
    • NCP(网络控制协议)：如IPCP，用于各网络层参数的协商
    • 认证协议：CHAP、PAP，保证网络安全性
  • 优点：支持同步和异步链路、良好的扩展性、提供认证协议
  • 应用场景：PPPoE(PPP over Ethernet)等接入场景，用于获取IP地址、DNS服务器等信息

以上协议在现代网络通信中扮演着重要角色，从底层数据传输到应用层服务，构成了互联网通信的完整体系。

Protocol Buffers

什么是 Protocol Buffers？

Protocol Buffers 是 Google 开源的结构化数据序列化机制，特点是：

• 体积小：二进制编码，远小于 JSON/XML；
• 速度快：序列化/反序列化速度快，开销低；
• 强类型：使用 .proto 文件定义字段，自动生成代码，避免类型错误；
• 版本兼容：字段有标签号（tag），支持新增字段而不破坏旧版本；
• 多语言支持：官方支持C/Java/Python/Go 等多种语言。

nanopb

为什么需要 nanopb？
标准的 Protobuf C/C++ 库体积较大，依赖动态内存分配，不适合资源受限的 MCU。nanopb 为嵌入式平台量身打造，具有以下特点：

• 超小体积：核心库仅几 KB，生成的代码也极小；
• 无动态内存：默认使用静态缓冲区，避免 malloc/free 带来的风险；
• 可配置性强：可以按需启用/禁用字段、回调；
• 开源：遵循 zlib 许可证，商业友好；
• 兼容 Protobuf：与官方工具链兼容，可与手机 App、服务器使用的 Protobuf 无缝对接。

应用场景

  1. 设备与手机 App 数据同步：
    • 方言：设备使用 nanopb 编码数据，通过 BLE/UART/WiFi 发送给 App
    • App 使用 Protobuf 库解析，显示设备状态
  2. 云端配置下发：
    • 云端服务使用 Protobuf 定义配置数据
    • 设备使用 nanopb 解码，实现配置下发
  3. 多平台统一协议：
    • 同一产品线的 ARM Linux、RTOS MCU、手机 App 共享同一个 .proto
    • 实现协议标准化，减少维护成本
  4. 数据日志与存储：
    • 使用 Protobuf 将数据记录到 Flash 或 SD 卡
    • PC 端工具使用 Protobuf 解析日志

总结

借助 Protocol Buffers + nanopb，可以在嵌入式设备建立一种高效、可靠、可扩展的数据交换机制，轻松应对复杂数据结构和跨平台兼容性问题。

学习方法及路线

嵌入式学习路线

1. 嵌入式学习的三个阶段

第一阶段：裸机开发 (Bare Metal)

这是直接在芯片上“裸奔”写程序。你不需要操作系统，直接操控寄存器。

  • 重点： C语言（指针、位运算）、单片机架构（如 STM32/ARM Cortex-M）、GPIO、中断、UART、I2C、SPI。
  • 目标： 理解底层硬件是如何工作的。当你点亮第一个 LED 灯时，你就完成了硬件控制的第一步。

第二阶段：嵌入式 Linux 系统 (Embedded Linux)

当任务变得复杂（需要网络协议栈、文件系统、图形界面）时，我们就需要 Linux。

  • 重点： Linux 常用命令、Shell 脚本、交叉编译 (Cross-Compilation)、Bootloader (U-Boot)、内核移植、根文件系统构建。
  • 目标： 让 Linux 在你的开发板（如树莓派、飞凌、正点原子等）上跑起来。

第三阶段：驱动开发与应用开发

这是目前行业内需求最大的部分。

  • 应用层： 使用 C/C++、Python 或 Qt 开发运行在 Linux 上的应用程序。
  • 驱动层： 编写连接硬件与 Linux 内核的桥梁（如字符设备驱动）。

2. 快速上手的“黄金建议”

建议你不要只看书，要**“以项目驱动学习”**：

  1. 准备一块开发板： 如果你是完全的新手，STM32 是学习裸机的首选；如果你想直接攻克 Linux，树莓派 (Raspberry Pi) 或 基于 IMX6ULL 的开发板非常适合。
  2. 不要纠结于背后的深层原理： 先通过“抄”代码让程序跑通，看到现象后再去深挖底层的寄存器配置或内核源码。
  3. 拥抱 Linux 环境： 尽早抛弃 Windows 下的各种 IDE，学会使用 Ubuntu 系统，尝试在终端里用 gcc 编译你的第一个 “Hello World”。

3.学习的过程中要有所总结和记录

  1. 总结是为了整理自己学到的东西，在整理的过程中发现自己对所学的知识的掌握
  2. 记录主要有两个目的：1.自己遗忘时可随时打开回顾；2.为自己工作/升学面试所使用的简历添加内容（当然作为学生竞赛获奖也能证明自己的实力）
