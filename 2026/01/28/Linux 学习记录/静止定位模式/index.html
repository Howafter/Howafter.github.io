GNSS 静止状态定位功能实现文档

功能概述

本功能为GNSS定位系统添加了智能的静止/动态状态检测和数据管理机制。当设备静止时，系统自动切换到低功耗模式，定期保存最优的定位数据；当设备运动时，按原有逻辑进行定位。

核心功能特性

1. 运动状态检测（3种模式）

模式1：基于速度判断

  • 判断标准：速度 < 0.1 km/h
  • 适用场景：速度数据可信的环境

模式2：基于位置偏移判断

  • 判断标准：与上一个定位点的距离 < 可配置阈值（默认50米）
  • 适用场景：GPS信号不稳定，但可靠GPS坐标的环境

模式3：组合模式（推荐）

  • 判断标准：两个条件都满足
  • 优势：最可靠，能有效过滤误判

2. GNSS数据滤波

系统对定位数据进行多维度评分，自动保留最优的定位点：

评分维度：

  • HDOP值（水平精度因子）

    • ≤1.5：0分（最优）
    • ≤3.0：10分
    • ≤5.0：20分

    • 5.0：50分（差）

  • 定位质量标志（0=无效，1=有效）

    • 有效：0分
    • 无效：100分

  • 卫星数量

    • ≥10颗：0分（最优）
    • ≥7颗：5分
    • ≥4颗：15分
    • <4颗：50分（差）

  • 定位状态（A=有效, V=无效）

    • 有效(A)：0分
    • 无效(V)：100分

评分越低说明定位点质量越好，系统自动保留评分最低的N个点。

3. 定时器管理

系统新增一个独立的静止状态定位定时器：

  • 静止状态定位间隔：30分钟（默认可配置）
  • 启动/停止：通过 static_location_timer_start() 和 static_location_timer_stop() 控制

配置参数

通过MQTT远程配置

命令类型 参数 说明
cfg.static.period period_seconds 静止状态定位间隔（秒）
cfg.static.mode mode (1-3) 运动检测模式（1=速度，2=位置，3=组合）
cfg.static.threshold threshold_meters 位置偏移阈值（米）
cfg.static.best count (1-10) 滤波后保留的最优点数

工作流程

  1. 获取定位数据

    • gnss_main.c 通过 nmea_parse_packet() 获得新的定位数据
    • 调用 gnss_static_buffer_add() 传入定位数据

  2. 状态判断

    • 根据配置的运动检测模式判断设备是否静止
    • 保存当前定位点为”上一个有效点”

  3. 数据管理

    • 如果静止：保存定位点到缓冲
    • 如果运动：按原有逻辑处理

  4. 定时上报

    • 静止状态定位定时器触发时，发送保留的最优定位数据
    • 每30分钟（可配）强制发送一次，保持设备在线

  5. 远程配置

    • 后台通过MQTT下发配置命令
    • 设备实时更新相关参数

    • 在 nmea_parse_packet() 中调用 gnss_static_buffer_add()

注意事项

  1. 内存占用：最多占用 sizeof(gnss_t) * 10 个字节的额外内存用于缓冲

  2. 精度权衡：建议使用组合模式（mode=3）获得最高的准确性

  3. 电源管理：静止时应配合PM模块降低功耗

  4. 时间戳同步：确保RTC时间准确，影响距离计算的精确性
