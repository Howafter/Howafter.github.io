博客撰写方法

三种适合嵌入式开发者的博客方案，按从易到难排序：

1. 极简方案：静态博客（推荐方案）

这是目前程序员的主流选择，原理是：你用 Markdown 写文章，工具将其渲染成 HTML 静态网页，托管在 GitHub 或 Gitee 上。

工具组合： Hexo 或 Hugo + GitHub Pages。

优势： * 免费：不需要买服务器和域名。

极客感：支持 LaTeX 公式（写算法）、代码高亮（写 C 语言）。

备份方便：文章就是一个个 .md 文件，配合 Git 管理，永远不会丢失。

全志开发板联动： 你甚至可以尝试在你的全志开发板上安装 Node.js，在板子上跑 Hexo 生成博客，这本身就是一个很好的嵌入式 Linux 实践。

1.1.5. 嵌入式博主的进阶：如何同步双环境？

既然你有 Windows 和 Linux 两个环境，最头疼的就是同步问题。

推荐策略：

  1. 在 GitHub 上再开一个私有仓库，专门存放博客的源码（也就是你本地的整个 blog_folder）。

  2. 在 Windows 下写完代码后，git push 到私有仓库。

  3. 回到 Linux 环境，git pull 拉取最新代码。

  4. 这样你无论在哪里，只要有 Git，就能随时更新博客。

    Markdown 本身很随意，但 Front Matter（YAML 格式）极其死板。如果你的博客不更新，通常是触发了以下地雷：

特殊符号引号：如果标题里包含冒号（例如 笔记: open()函数），必须用引号包起来：title: “笔记: open()函数”，否则会解析报错。

2. 社区方案：现成平台

如果你不想折腾环境，只想立即开始写：

推荐： CSDN、掘金、知乎 或 博客园。

优势： 自带流量，别人容易搜到你的笔记，互动多。

缺点： 页面不够自定义，广告较多，数据不在自己手里。

3. 硬核方案：自建 WordPress

工具： 购买云服务器 (阿里云/腾讯云) + 安装 WordPress 镜像。

优势： 功能最全，有后台管理界面，像写文档一样方便。

缺点： 每年需要续费服务器，且容易受到网络攻击，需要维护。
