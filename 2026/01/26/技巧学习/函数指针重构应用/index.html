函数指针重构应用

在嵌入式软件开发中，从简单的回调函数到复杂的状态机，从启动代码到驱动框架，函数指针几乎无处不在。

回调函数表

背景

在嵌入式开发中，经常需要处理不同的命令、事件或消息。传统的做法是使用switch-case语句：

这种方式存在问题：

  • 新增命令需要修改switch-case结构
  • 代码冗长，可读性差
  • 难以动态扩展
  • 不符合开闭原则（OCP）

解决策略

回调函数表的核心思想是：将函数指针存储在数组中，通过索引直接调用对应的函数 。

解释一下 cmd_table[cmd]() 这个表达式，这是 C 语言中使用函数指针数组的常见方式。

首先，让我们理解 cmd_table 是什么：

cmd_table 是一个函数指针数组，每个元素都是一个 CommandHandler 类型的指针，即指向 void(void) 函数的指针。

在 C 语言中，函数指针的调用方式与普通函数调用非常相似。当你有函数指针 func_ptr 时，调用它的方式是 func_ptr()。

所以，cmd_table[cmd] 是从数组中取出的函数指针，而 cmd_table[cmd]() 就是调用这个指针指向的函数。

让我用一个简单的例子来说明：

在上面的例子中，func_array[0] 是一个指向 greet 函数的指针，func_array[0]() 就是调用 greet 函数。

回到你的代码：

  • cmd_table[cmd] 是一个函数指针
  • cmd_table[cmd]() 是调用这个函数指针指向的函数

C 语言允许省略函数指针的解引用操作符 *，所以 cmd_table[cmd]() 等同于 (*cmd_table[cmd])()，但前者更简洁，是 C 语言的惯用写法。

在你的代码中，process_command 函数会根据传入的命令类型 cmd，从 cmd_table 中找到对应的函数指针，然后调用它。如果 cmd 无效，就调用 handle_unknown()。

例如：

  • 如果 cmd = CMD_START，则 cmd_table[CMD_START] 是 handle_start 函数的指针，cmd_table[CMD_START]() 就是调用 handle_start()。
  • 如果 cmd = CMD_STATUS，则 cmd_table[CMD_STATUS]() 就是调用 handle_status()。

这是一种常见的回调机制实现方式，用于实现命令处理表。

底层初始化中应用

启动代码

在嵌入式系统中，启动代码（Startup Code）是系统上电后执行的第一段代码。它负责：

  1. 初始化堆栈指针
  2. 初始化数据段（.data）
    1. 清零BSS段（.bss）
    1. 调用系统初始化函数
    1. 跳转到main函数

函数指针在启动代码中扮演着重要角色，特别是在中断向量表和初始化函数表的实现中。
