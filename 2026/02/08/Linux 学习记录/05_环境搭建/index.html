SSH安装&VSCode客户端工具安装

经过前面的课程，想必大家都已经熟悉一些常用的Linux命令使用了，但是我们还存在一个问题，就是在vi文本编辑器下，写代码效率其实很低，没有补全，没有错误提示，虽然现在也有各种魔改，把vim改为接近vscode这类ide，但是不建议大家花时间整这个，我们直接一步到位，使用VSCode即可。

下面我们会使用VSCode，通过SSH访问Ubuntu，实现在window的VSCode中，编辑，编译Linux中的代码。

ubuntu下ssh安装

Window安装VSCode，略…

如果你使用Ubuntu1804，那VSCode版本必须小于或等于1.85.2，否则后面SSH会连接失败，如果用Ubuntu2004或者Ubuntu2204，那可以安装最新的VSCode版本。

Window的VSCode中，安装Remote - SSH插件

左侧打开插件，配置需要登陆的Ubuntu主机ip，还有用户名xiaozhi，端口默认为22

安装完成后，我们就可以使用VSCode进行代码编写和编译了。

问题1：

如果遇到VScode ssh突然连接报错

这是VS Code版本更新导致：2024年2月发布的VS Code 1.86版本提高了对远程服务器的要求，特别是glibc和libstdc++的版本12，建议重新安装低版本vscode，设置禁止自动更新。

问题2：

如果遇到VSCode ssh访问失败，提示”过程试图写入的管道不存在。“

1、排查下window ip和ubuntu ip是否在同一网段，然后在命令行窗口互ping对方，看能否ping得通，如果ping不通修改下虚拟机网络连接方式重试

2、删除电脑C:\Users\你的用户名.ssh\下的的known_hosts文件，重新连接

问题3:

如果之前安装完成可以连接，然后某天突然连接不上了

1、一般情况下是vscode没有关闭自动更新，然后升级为其它版本了，卸载重装，然后设置禁止自动更新

2、排查下window ip和ubuntu ip是否在同一网段，然后在命令行窗口互ping对方，看能否ping得通，如果ping不通修改下虚拟机网络连接方式重试

3、 ubuntu中查看ssh是否运行ps -e|grep ssh

4、删除电脑C:\Users\你的用户名.ssh\下的的known_hosts文件，重新连接

Makefile工程搭建

Makefile 是一个用于自动化构建（编译、链接、安装等）的脚本文件，通常用于管理包含多个源文件的软件项目。它定义了源文件、依赖关系以及如何生成目标文件或最终可执行文件的规则。

对比维度 手写编译指令 Makefile构建 CMake构建
基本概念 在指令行手写输入编译器（如GCC）命令来编译和链接代码文件，每次编译都需要完整输入命令。 编写Makefile文件描述项目文件依赖关系和编译规则，使用make命令一句该文件自动编译项目。 编写Makefile文件描述项目构建信息，CMake依据此文件生成不同平台得到Makefile或其他构建文件，再用对应工具编译。
自动化成都 低，每次修改代码后都要手动输入完整编译命令，易出错且效率低。 高，make命令可根据文件修改时间自动判断那些文件需要重新编译，避免不必要的重复编译。 高，CMake能自动检测系统环境和依赖库，生成合适的构建文件，进一步提高自动化程度
可维护性 差，项目结构或依赖关系变化时，需手动调整编译命令，容易遗漏或出错 较好，在Makefile中清晰定义文件依赖和编译规则，修改和拓展项目时只需要调整Makefile内容。 好，CMakeLists.txt文件独立于具体平台和构建工具，修改项目配置时只需修改该文件，CMake会重新生成相应构建文件。
适用场景 小型项目、学习阶段或需快速验证代码的情况。 中等规模项目，项目结构相对稳定、依赖关系明确。 大型项目、跨平台项目或需与不同开发工具继承的项目。
