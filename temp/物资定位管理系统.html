物资定位管理系统完整技术方案

1. 系统概述

本系统基于 Air780EG 模组（集成 4G LTE + GNSS）与 NRF52832（集成 UWB DW1000 + BLE + Sub-1G），实现多模态物资定位管理。系统通过四条独立的数据线路获取、处理并上报定位数据，最终汇聚至云平台进行统一管理与展示。

2. 硬件架构

核心组件

  • 主控 MCU: Air780EG (EC618) - 负责 4G 通信、GNSS 解析、业务逻辑调度
  • 协处理器: NRF52832 - 负责 UWB/BLE/Sub-1G 射频数据采集
  • 定位芯片: AT6558 (支持 GPS+BDS+GALILEO)
  • 通信模块: 4G LTE Cat.1

3.1.3 数据发送 (4G MQTT)

文件: _client.c → __report_data_pack()

  • 打包格式 (JSON):

    • 字段说明:
      • [0]: Unix 时间戳 (秒)
      • [1]: 运动状态 (0=静止, 1=运动)
      • [2]: 锚点 ID
      • [3]: TDOA 序列号 (保留，填 -1)
      • [4]: TOF 序列号 (保留，填 -1)
      • [5]: RSSI (dBm)

    • 批量上报: 缓冲区达到 DIST_REPORT_DATA_MAXLEN (30条) 或超时 60s

  • 定位解算:
    • 使用三边测量法 (Trilateration) 计算物资坐标
    • 输入: 至少 3 个锚点的距离数据
    • 输出: (X, Y, Z) 三维坐标
  • 应用场景:
    • 室内高精度定位 (精度 10-30cm)
    • 电子围栏告警
    • 轨迹回放

3.3 Sub-1G 传感器数据线路

3.3.1 数据获取

  • 硬件链路: Sub-1G 传感器节点 → NRF52832 (Sub-1G Receiver) → Air780EG (SPI)

  • 通信协议: 自定义二进制协议 (带 CRC16 校验)

  • 数据类型:

    1. 心跳包 (SUB1G_REPORT_TYPE_HEARTBEAT): 包含设备状态、电池电压
    2. 传感器数据 (SUB1G_REPORT_TYPE_SNSR): 步数、气压计数据
    3. GPS 透传 (SUB1G_REPORT_TYPE_GPS): 子设备自身 GNSS 数据
    4. 混合报告: 包含多种节点类型

    • 运动检测: 基于速度 (< 0.1 km/h) 和位置漂移 (< 50m) 判断静止
    • 数据滤波: 积累 10 个点后，根据 HDOP、卫星数、Fix Quality 评分，保留最优 5 个点

3.4.3 数据发送 (4G MQTT)

文件: _client.c → process_and_publish_gnss_data()

  • 常规上报格式 (JSON):

    • GNSS 数据字段:
      • [0]: Unix 时间戳
      • [1]: 运动状态
      • [2]: 纬度 (度, 6位小数)
      • [3]: 经度 (度, 6位小数)
      • [4]: 海拔 (米, 2位小数)
      • [5]: HDOP (2位小数)
      • [6]: Fix Quality (0=无效, 1=GNSS, 2=DGPS, 4=RTK Fixed)
      • [7]: 卫星数
      • [8]: 定位模式 (A=自主, D=差分, E=估算, N=无效)
      • [9]: 状态 (A=有效, V=无效)
      • [10]: 速度 (km/h, 3位小数)
      • [11]: 航向 (度, 2位小数)

  • 静止状态优化上报 (process_and_publish_static_gnss_data()):

    • 使用过滤后的最优点集合 (best_points[])
    • 时间戳采用服务器当前时间 (time(NULL)) 而非 GNSS 原始时间
    • 其他字段与常规上报相同

  • 上报触发机制:

    1. 定时上报: timer_report 定时器 (默认 40s)
    2. 手动查询: 收到 MQTT 命令 req.location.msg
    3. 批量策略: 缓冲区达到 GNSS_REPORT_DATA_MAXLEN (30条) 或超时 60s

  • 数据存储:
  • 业务逻辑:
    • 轨迹回放: 按时间顺序绘制移动路径
    • 地理围栏: 判断坐标是否在预设区域内
    • 超速告警: 速度 > 阈值时触发
    • 定位质量评估: HDOP < 2.0 为高精度，> 5.0 为低精度
    • 静止检测: 连续多点坐标不变且速度为 0，判定为停车/停留

5. 平台端数据接口规范

5.1 MQTT Topic 定义

  • 上行数据 (设备 → 平台):

    • /dev/{imei}/uplink/status - 设备状态心跳
    • /dev/{imei}/uplink/location - 定位数据上报
    • /dev/{imei}/uplink/alarm - 告警事件 (SOS、低电量等)

  • 下行命令 (平台 → 设备):

    • /dev/{imei}/downlink - 通用命令通道
      • {"type": "cfg.gnss.period", "val": 40} - 设置 GNSS 定位周期
      • {"type": "cfg.rpt.period", "val": 40} - 设置数据上报周期
      • {"type": "req.location.msg"} - 手动触发定位上报
      • {"type": "cfg.static.period", "val": 1800} - 设置静止状态上报周期

5.2 数据完整性保障

  • 序列号机制: 全局递增 SEQ 字段，平台端检测丢包
  • CRC 校验: Sub-1G 链路层 CRC16，应用层 JSON 格式校验
  • 重试机制: MQTT QoS 1，确保至少送达一次
  • 断点续传: 网络恢复后，优先上报积压的环形缓冲区数据

5.3 异常处理

异常场景 处理策略
GNSS 长时间无信号 切换为 BLE/UWB 定位，标记 fix_quality=0
4G 网络断开 数据缓存至 Flash，网络恢复后补传
电池电量 < 10% 降低 GNSS 频率至 300s，关闭 UWB/BLE 扫描
NRF52832 通信失败 重试 100 次后判定硬件故障，上报告警
SOS 报警触发 立即上报，忽略批量策略，优先级最高

7. 总结

本方案通过 UWB + BLE + Sub-1G + 4G GNSS 四线并行的架构，实现了：

  1. 全场景覆盖: 室内高精度 (UWB) + 室外广域 (GNSS) + 过渡区辅助 (BLE)
  2. 低功耗优化: 基于运动状态的自适应采样与上报策略
  3. 多源融合: 多种定位技术互补，提升可靠性
  4. 实时告警: Sub-1G 传感器直连，SOS 毫秒级响应
  5. 云端协同: 标准化 MQTT 接口，支持远程配置与 OTA 升级

该系统适用于 物流仓储、人员安全监护、资产追踪、智慧工地 等多种物联网应用场景。
