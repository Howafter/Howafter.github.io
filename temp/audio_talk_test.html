语音对讲功能测试（面向小白）

说明：本指南面向初学者，覆盖从环境准备到端到端验证（MQTT 控制 + RTP 下行/上行）的逐步操作与常见问题排查。****

一、前置条件（必做）

  • 设备固件已烧录并运行，能通过串口查看日志。常见初始化日志：MQTT Audio Command Handler Init。
  • 设备与测试 PC 在同一局域网（避免 NAT 问题）。
  • PC 上安装：
    • mosquitto-clients（用于发布/订阅 MQTT）
    • gstreamer（包含 gst-launch-1.0）或 ffmpeg（用于生成/接收 RTP 流）
    • 可选：wireshark（抓包调试）
  • 准备一份 AMR-NB 测试音频文件 sample.amr（8kHz），放在 PC 可提供的 HTTP 服务或本地路径。

二、关键源码位置（便于查日志/定位）

  • MQTT 命令处理：project/airocov_780E_at6558/audio/audio_talk/mqtt_audio.cmd.c
  • RTP 接收/抖动缓冲与 AMR 解码播放：project/airocov_780E_at6558/audio/audio_talk/voice_talk.c
  • HTTP 下载与播放控制：project/airocov_780E_at6558/audio/audio_talk/audio_ctrl.c

三、测试清单（逐项完成并记录结果）

  • 环境检查（能连 MQTT，能查看串口日志）
  • MQTT 控制：audio.play/stop/pause/resume 响应正确
  • RTP 下行（PC → 设备）：PC 发送 RTP AMR，设备能播放
  • RTP 上行（设备 → PC）：设备采集并发送 RTP，PC 能接收播放
  • 日志与抓包：能定位异常（心跳、RTP 超时、重连）

5) 捕获/分析网络包（可选）

  • 在 PC 上用 wireshark 捕获 udp.port == 5004，查看 RTP 包是否到达，检查序列号/SSRC/有效载荷长度。

五、常见问题与排查建议

  • 无 MQTT 响应：检查设备是否连上 Broker，topic 名称是否匹配；在设备串口查找订阅/收到命令的日志。
  • audio.play 启动失败但返回 success：确认实际 audio.status 报文反映下载/播放状态（downloading/playing/error）。
  • 下行无声：确认 audio.talk.state 为 listening，确认 PC 的 RTP 包能到达设备（用 Wireshark 抓包），确认 voice_talk_jitter_playout 被触发。
  • 上行无声：确认 voice_talk_start_speak 返回 0，确认 I2S 驱动与麦克风硬件就绪，并在串口中查找 luat_i2s_start 或 record_cb 相关日志。
  • 网络穿透问题：当前实现不包含 STUN/TURN，要在同一局域网或做好端口映射。

六、扩展（可选）

  • 启用回声/降噪：在 voice_talk.c 中开启 VOICE_TALK_ENABLE_SPEEXDSP 并添加 speex 库，重新编译；在嘈杂环境下值得开启。
  • 自动化脚本：可把常用 mosquitto_pub 与 gst-launch 命令写成 .sh / .bat 脚本，便于重复测试。
